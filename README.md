# Место

Решение задания № 9 «Регистрация на мероприятия».
Минимальный сервис регистрации на мероприятия: места и FIFO-лист ожидания,
отмена участия, билеты, однократный чекин и live-статистика организатора.

**Стек:** Python 3.12, FastAPI, Pydantic 2, async SQLAlchemy + asyncpg,
PostgreSQL 17, Alembic, uv; React, TypeScript, Vite, Nginx.

## Запуск

Предварительные требования: Git, запущенный Docker Engine или Docker Desktop
с Compose v2, Python 3 для подготовки локального `.env` и свободные порты
8080 и 8081. Зависимости приложения устанавливаются внутри контейнеров.

Первый запуск из нового клона:

```sh
git clone https://github.com/vladbily/maddevs-tz.git
cd maddevs-tz
python3 scripts/setup_local.py
docker compose up --build
```

Откройте [localhost:8080](http://localhost:8080), а для создания первого события —
[кабинет организатора](http://localhost:8081/organizer). Пароль — значение
`ORGANIZER_PASSWORD` в созданном `.env`. Последующие запуски:
`docker compose up --build`. Без `.env` публичная часть работает, а вход
организатора отключён. Данные сохраняются в Docker volume.
Миграции выполняются автоматически. Остановка: `docker compose down`.

## Доступ организатора

Кабинет: [localhost:8081/organizer](http://localhost:8081/organizer).
На публичном порту 8080 нет кнопки входа; страницы `/login`, `/organizer`,
API `/api/auth/*`, `/api/organizer/*` и API-документация возвращают 404,
в том числе с действующей cookie или подменённым `Host`.

Скрипт `scripts/setup_local.py` создаёт `.env` с правами 0600,
двумя независимыми случайными секретами
и не перезаписывает существующий файл. Пароль берётся из `ORGANIZER_PASSWORD`
в этом файле; не публикуйте его. `.env` исключён из Git. Если файл уже есть,
задайте в нём новый случайный пароль (16–256 символов) и независимый
`SESSION_SECRET` (от 32 символов); можно использовать `secrets.token_urlsafe`
или менеджер паролей. Старые публичные значения по умолчанию больше не работают.
При смене пароля меняйте и `SESSION_SECRET`, чтобы завершить старые сессии.

После 5 неверных попыток подряд новый вход блокируется на 15 минут с ответом
429 и `Retry-After`. Счётчик общий для единственного организатора, хранится
в PostgreSQL и блокируется транзакционно: смена IP, параллельные запросы и
рестарт backend его не обходят. Запросы во время блокировки её не продлевают,
активные сессии продолжают работать. Успешный вход сбрасывает счётчик.
Это следует подходу [OWASP к ограничению попыток входа](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#login-throttling).

Оба порта Compose привязаны к `127.0.0.1`. На сервере публикуйте основной
сайт через HTTPS reverse proxy на порт 8080. Порт 8081 и backend напрямую
в интернет не открывайте. Укажите в `.env` `PUBLIC_URL=https://events.example.com`
(ваш публичный домен) и пересоберите frontend через `docker compose up -d --build`:
ссылки-приглашения из кабинета будут вести на этот адрес. Локально по умолчанию
используется `http://localhost:8080` (или настроенный `APP_PORT`).
Для удалённого кабинета достаточно SSH-туннеля:

```sh
ssh -N -L 8081:127.0.0.1:8081 user@server
```

После этого откройте локальный адрес кабинета. Альтернатива — поддомен
`organizer.example.com` с HTTPS reverse proxy на `127.0.0.1:8081`,
с доступом только через VPN или список разрешённых IP. Для поддомена задайте
`COOKIE_SECURE=true`; proxy должен сохранять исходный `Host` вместе с портом,
если он нестандартный. Cookie не имеет общего `Domain`, доступна только
HTTP API и помечена `HttpOnly`/`SameSite=Strict`. Само название поддомена
не является защитой. Разделение портов обеспечивается Nginx в Docker;
Vite dev server не предназначен для внешнего размещения.

## Уведомления

Почтовых интеграций нет: «отправка» означает запись в `notifications`.
Код билета и ссылку управления можно получить из БД:

```sh
docker compose exec postgres psql -U events -d events -c \
  "SELECT id, email, created_at, kind, code, payload FROM notifications ORDER BY id DESC;"
```

Одна фоновая задача раз в 10 секунд создаёт напоминания всем активным
участникам: владельцам мест и участникам листа ожидания, исключая отменённые
регистрации. Напоминание создаётся, когда до события остаётся не больше суток.
Каждому email на событии — максимум одно напоминание, даже после переноса.
Поздние регистрации получают его ближайшим проходом. Перенос создаёт
отдельные уведомления подтверждённым и ожидающим участникам.
Получение места из очереди не создаёт повторного напоминания. После простоя
сервера пропущенные напоминания создаются, пока событие ещё не началось;
после начала события они не досылаются.

## Решения по архитектуре

FastAPI и Pydantic дают асинхронный HTTP API с проверкой входных данных.
SQLAlchemy и asyncpg позволяют использовать транзакции и блокировки PostgreSQL:
изменения мест и уведомления фиксируются вместе, а параллельные регистрации
не превышают лимит. Alembic хранит изменения схемы, uv.lock — версии Python-зависимостей.
React и TypeScript дают общий набор компонентов и типизированный контракт API.
Docker Compose собирает весь стек для одинакового локального запуска.

## Разработка с AI

Инструмент разработки — Codex, модель — GPT-6 Sol. Этот набор использован для
реализации, анализа транзакций, ревью и подготовки тестов в одном рабочем каталоге.
Codex выбран для работы агента с файлами и командами проекта; модель применена
для последовательной реализации и разбора конкурентных сценариев с проверкой
результатов тестами. Промпты, решения и этапы работы с временными отметками
сохранены в [WORK_LOG.md](WORK_LOG.md).

## Состояние и дальнейшие планы

Реализованы создание и редактирование событий, регистрация без дублей,
FIFO-очередь с автоматическим продвижением, отмена, билеты, однократный чекин,
live-статистика, уведомления о переносе и однократные напоминания.
Проверки включают конкурирующие запросы и работу двух браузерных клиентов.

Ограничения MVP выбраны для небольшого объёма задания: один организатор,
один backend-процесс и эмуляция почты в PostgreSQL. Чекин использует ручной
ввод кода; интерфейс чтения уведомлений и пагинация списков пока не реализованы.

Расширенный браузерный аудит, описанный в WORK_LOG.md (R9), выявил оставшиеся
замечания: устаревание карточек общих списков, задержки запросов при шести
открытых SSE-вкладках, переход к билету после ухода со страницы регистрации
при позднем ответе и перекрытие текста декором при ширине 701 px.

Следующим заходом исправил бы эти замечания, затем добавил просмотр уведомлений
в кабинете и пагинацию мероприятий и участников. Настоящую отправку почты —
при переходе от демо к использованию реальными участниками.

## Разработка

Все проверки, включая гонки на PostgreSQL и браузерный сценарий:

```sh
./scripts/test.sh
```

Тесты запускаются в отдельном Compose-проекте без открытых портов; его
контейнеры и данные удаляются после проверки. Скриншоты — в
`frontend/test-results/`. Такие же проверки запускаются в GitHub Actions.

Правила — в AGENT.md, запросы и этапы работы — в WORK_LOG.md.
Сервис рассчитан на один backend-процесс и одного организатора.
Все изменения мест транзакционны; даты хранятся в UTC.
API-документация доступна на приватном порту:
[localhost:8081/api/docs](http://localhost:8081/api/docs).
