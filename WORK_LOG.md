# Минимальный сервис регистрации на мероприятия

## Результат и стек

Создать публичный монорепозиторий `vladbily/maddevs-tz` с работающим приложением, тестами, краткой документацией и двумя субагентами.

## Данные и поведение

**Три основные таблицы:**

- `events`: название, описание, дата и время, лимит мест, версия расписания.
- `registrations`: событие, нормализованный email, статус `confirmed/waitlisted/cancelled`, время постановки в очередь, код билета, секретный токен управления, время чекина.
- `notifications`: ID, email, время создания, тип уведомления, код билета при наличии, связь с регистрацией, данные сообщения и уникальный ключ для защиты от дублей.

Уведомление считается отправленным при создании записи в `notifications`. Реальной отправки нет. В README будет команда просмотра таблицы через `docker compose exec postgres psql`.

**Регистрация и очередь:**

- Email нормализуется через удаление внешних пробелов и приведение к нижнему регистру. База обеспечивает уникальность пары «событие + email».
- Регистрация, отказ, изменение вместимости и продвижение очереди выполняются в транзакции с блокировкой строки события. Это сериализует конкурирующие операции с последним местом. [Блокировки PostgreSQL](https://www.postgresql.org/docs/17/explicit-locking.html).
- При наличии места выдаётся билет; иначе участник попадает в FIFO-очередь.
- Отказ подтверждённого участника сразу продвигает первого ожидающего и создаёт уведомление с билетом в той же транзакции.
- Повторная активная регистрация не занимает место и не создаёт уведомление повторно. Она не раскрывает существующие секретные ссылки и код билета.
- После отказа разрешена повторная регистрация: переиспользуется запись, обновляются секреты, очередь отсчитывается заново. Старые ссылки и билеты перестают действовать.
- Уменьшение лимита ниже количества занятых мест запрещено; увеличение продвигает ожидающих по порядку.

**Билеты, время и уведомления:**

- Новый участник получает секретную ссылку для просмотра регистрации и отказа; она также сохраняется в уведомлении. У ожидающего билет появляется после получения места.
- Чекин доступен организатору по коду и проходит только один раз. Повтор возвращает понятное сообщение «Билет уже использован».
- Регистрация и отказ доступны до начала события; после чекина отказ запрещён.
- Фоновая задача каждые 10 секунд создаёт напоминания подтверждённым участникам, если до начала осталось не больше суток.
- Поздняя регистрация или продвижение из очереди получает напоминание на ближайшем проходе задачи. После перезапуска пропущенные напоминания создаются, пока событие ещё не началось.
- Напоминание уникально для регистрации за всё событие: перенос и повторная регистрация после отказа не сбрасывают это правило.
- При фактическом изменении даты уведомления получают подтверждённые и ожидающие участники. Повторное сохранение той же даты ничего не создаёт.
- Уведомления о билетах различаются по коду, о переносах — по версии расписания. Это позволяет корректно выдавать новый билет и неоднократно переносить событие.
- Даты хранятся в UTC; интерфейс показывает локальное время с часовым поясом.

## API и интерфейс

API под `/api` включает:

- публичный список и просмотр событий, регистрацию по email;
- просмотр регистрации и отказ по секретному токену;
- вход и выход организатора;
- защищённые создание и редактирование событий, список участников, статистику и чекин;
- SSE-поток статистики и healthcheck.

Один организатор входит по паролю из настроек. Авторизация использует подписанную cookie с `HttpOnly` и `SameSite=Strict`. Для запуска без подготовки предусмотрены локальные настройки по умолчанию; их замена описана в README.

Интерфейс на русском языке: список событий, страница события, страница билета/ожидания, кабинет организатора и экран чекина. Светлая тема, адаптивная вёрстка, понятные ошибки, состояния загрузки и пустых списков.

- два участника на последнее место;
